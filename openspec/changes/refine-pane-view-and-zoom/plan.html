Pane view and zoom

Close buttons on split areas stop killing shells, one pane can take the window while the rest keep running, and zoom acts on the pane, folder or window that has focus.

Proposed, uncommitted Awaiting review x-plan-page: accepted · core, host, UI · 1 PR

Change refine-pane-view-and-zoom on branch feature/pane-view-zoom, from origin/develop 19625b4. Page built 2026-11-12 from proposal.md, design.md and tasks.md.

01Why now

A split screen has no way back to one pane. The area head’s × runs Close pane, which ends the shell and, with the last pane, the tab and its row. ⌘⇧M only maximizes until pressed again.

Zoom is one setting for every window, so a person can’t enlarge one Claude session on a projector or shrink a log pane beside it.

focus→pane · folder · window→SetPaneZoom / SetWindowZoom→notice

Tinted boxes are new: the focus-scoped target and the two core commands.

03Decisions

D1The area × hides; Close pane leaves the head.

The × runs the same hideRow path as the palette’s “Hide from the window…”. Close pane stays on ⌘W, the Shell menu and the pane menu, with its busy-shell confirmation. Rejected keeping × as Close pane beside a new hide icon: two icons side by side invite the wrong click.

D2Show Alone composes existing moves.

The UI sends one PaneToTab per other pane, in reading order, then sets the view to the focused tab. No new core command. Rejected a core ShowAlone command: it duplicates PaneToTab’s move logic, and a half-done Show Alone still leaves every pane running.

D3⌘⇧M keeps its meaning.

Maximize stays temporary per tab; Show Alone is the persistent one. Rejected making ⌘⇧M persistent: people rely on the second press to get the split back.

D4Pane zoom is a field on the layout leaf.

Layout::Pane gains optional zoom in layout_json, so it needs no migration and moves with the pane. SetPaneZoom takes several pane ids, so a folder zoom is one persist and one broadcast. Rejected a pane_zoom table (cleanup and a join for one number), and localStorage (lost across windows and with site data).

D5A pane scales its own fonts.

Terminal font size × zoom, rounded to 0.5 px, then refit, which resizes the pty as a window resize does. Text and transcript panes do the same. Window zoom multiplies on top. Rejected CSS zoom on the pane: xterm.js measures cells in CSS pixels and misplaces cursor and selection.

D6Window zoom moves to the window row.

Migration 0015_window_zoom.sql adds nullable windows.zoom_percent; SetWindowZoom writes it; main.rs zooms that webview only. settings.zoom_percent becomes the zoom a new window opens at. Rejected storing it in frame_json: the host rewrites the frame on every move and resize, and a zoom write would race it.

D7Focus picks the target.

document.activeElement inside a pane zooms the pane; on a sidebar row or folder header, its panes; anywhere else, the window. Menu clicks keep webview focus, so the View menu matches the chords. Rejected a scope picker in Settings: a mode to remember, while focus already shows through the orange outline.

D8A folder steps from its selected pane.

Step the selected pane’s zoom and set that one value on every pane; ⌘0 clears all. Rejected stepping each pane from its own value: differences never converge and the notice can’t name one value.

D9Notice text.

Pane name · N%, Folder name · K panes · N%, Window · N%, with (max)/(min); “Already alone” for a no-op Show Alone. No ptyd change: PROTOCOL_VERSION stays 1.
