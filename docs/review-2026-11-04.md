# Plan review, 2026-11-04

This reviews `add-terminescu-foundation` at D1 to D30, before any product code exists. Two
checks against primary sources came first: the Claude Code hooks reference
(code.claude.com/docs/en/hooks, /env-vars, /interactive-mode) and the Tauri v2, WebKit and
xterm.js sources. The fixes are now D31 to D35 and edits to D7, D9, D10, D18 and D21, and the
change validates with `--strict`.

## Issues found and fixed

| # | Issue | Why it mattered | Fix |
|---|---|---|---|
| 1 | Waiting never cleared after a permission was approved | The plan hooked only `Notification`, `UserPromptSubmit` and `Stop`. Claude Code has no "approved" event, so the amber stayed on until the turn ended. | `PermissionRequest` sets Waiting. `PostToolUse` (every tool), `PostToolUseFailure` and `PermissionDenied` clear it (D34). |
| 2 | `idle_prompt` turned every finished session amber | A session that's done and waiting for its next prompt isn't asking for anything. Amber would have lost its meaning within the hour. | `idle_prompt` leaves the tab Done (D34). |
| 3 | Secrets got typed into the pane as ` export NAME=value` | The value echoed into the scrollback ring and needed `HIST_IGNORE_SPACE`. With Claude in the foreground it would have landed in Claude's input. Exports made after Claude started never reach Claude's Bash tool anyway. | The shell's `precmd` loads `terminescu var env`. The `SessionStart` hook writes the same line to `CLAUDE_ENV_FILE`, which Claude Code runs before each Bash command (D35). |
| 4 | "Claude only ever sees `$NAME`" overstated the protection | Claude's Bash tool runs as you and can call the CLI. | D35 says what secret mode protects against and what it doesn't. `var get` needs `--reveal`. |
| 5 | The daemon would die with the app | Tauri's shell plugin kills its sidecar children at exit, and the updater replaces the bundle the daemon runs from. | The app copies the daemon to Application Support and starts it with `setsid`, with a version handshake and "Restart sessions" for upgrades (D32). |
| 6 | Pty output path unspecified | Tauri events are JSON strings and the docs say they aren't built for throughput. | Raw bytes over `ipc::Channel`, batched per frame with acknowledgements (D33). |
| 7 | WebGL context limit | WebKit keeps 16 live WebGL contexts per content process and silently drops the oldest. Twenty terminals would have gone blank. | WebGL only for visible panes, DOM renderer otherwise and on context loss. xterm.js 6 has no canvas renderer (D33). |
| 8 | Hooks fire in every Claude session on the Mac | Hooks live in `~/.claude/settings.json`. A slow or noisy hook would have hurt Claude in iTerm too, and stdout from `SessionStart` reaches Claude's context. | The hook exits 0 without a pane id, prints nothing, gives up on the socket after 100 ms, and has a 5 s timeout (D34). |
| 9 | Status rules couldn't see the command | OSC 133 carries exit codes but no command text, so "`pnpm test` exits non-zero" had nothing to match. | The integration reports the command line from `preexec` (D9). |
| 10 | `EDITOR` in the spawn environment loses | `.zshrc` exports override it, and git reads `VISUAL` first. | The integration sets `VISUAL` and `EDITOR` after the rc files (D9, D27). |
| 11 | Spec contradictions | Secrets were "left out of merges" while merges move whole contexts. Two scenarios sat under the wrong requirement. `pairing_tokens` was in v1 with no use. | Secrets move in the daemon on merge. Scenarios moved. The table waits for `add-remote-view` (D18). |
| 12 | Scrollback was measured in "lines" of raw bytes | A raw ring has no cheap line count and loses state at width changes. | 8 MB byte ring with resize markers, capped at 10,000 lines (D31). |
| 13 | P1 was one 40-task block with the riskiest parts untested | A wrong guess about reattach or keys would surface after weeks of work. | Five spikes come first (tasks group 0). P1 ships in four usable milestones. |
| 14 | Repo hygiene | `render.mjs` hardcoded a path into another repo and a home folder. The design system JSON named a person. There was no `.openspec.yaml`. | All three fixed. |

## Risks that remain

- **Reattach of the Claude TUI** (D20, D31). Claude Code redraws inline. Raw replay at a
  different width may garble it. Spike 0.1 decides between raw replay and a headless screen
  model.
- **Cross-window drag** (P2, D20). Nothing confirms that WKWebView keeps sending pointer events
  outside the window during a drag. Cocoa does deliver `mouseDragged` to the source view. The
  fallback is polling `cursor_position()` from the core.
- **Claude Code drift.** Hook fields and tool names change between versions. `MultiEdit` and
  `NotebookEdit` aren't in the current tool list, and the docs don't say whether `⌃G` reads
  `VISUAL` or `EDITOR`. Spike 0.5 records real payloads as fixtures.
- **Daemon upgrades** need "Restart sessions" until ptys can be handed over between
  processes (fd passing is a possible later change).
- **Scope.** P1 still holds about 45 tasks for one person. The milestones keep each stretch
  usable, but text tabs (M4) are the first thing to slip.

## After the spikes (2026-11-04)

All five spikes ran the same day; notes in `docs/spikes/`. Each was a go, and three changed the
plan:

- 0.5: denying a permission prompt fires no hook, so Waiting clears from the transcript tail (D34).
- 0.1: raw replay is exact only until the ring drops its head; the daemon keeps a headless screen
  per pane and sends a snapshot on attach (D7, D20, D31).
- 0.2: CodeMirror's Tab left the editor; text panes bind Tab to indent (D27).

| Area | Before | After | Remaining gap |
|---|---|---|---|
| Claude awareness and needs-you (hooks) | 85% | 90% | Transcript-tail clear for denials is new code |
| Keys and the native menu | 80% | 90% | Settings › Keys conflicts, untested |
| Daemon lifetime and upgrades | 75% | 90% | Protocol N-1 path, signing and notarization |
| Output throughput and rendering | 75% | 85% | Numbers came from a heavily loaded machine |
| Reattach of `claude` after restart or move | 65% | 80% | Inactive-grid accessor, memory per pane |

Overall: **about 85% for P1.** The secrets path (`precmd` plus `CLAUDE_ENV_FILE`) stays at 80%;
its `precmd` cost is now measured at about 10 ms per prompt.
